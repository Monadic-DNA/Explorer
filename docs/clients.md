# Web, Android, and iOS clients

Explorer has three separate UIs backed by one Rust library:

- `app/`: Next.js/React web UI and the existing HTTP backend.
- `apps/android/`: Kotlin, Jetpack Compose, Android 8+ (API 26).
- `apps/ios/`: SwiftUI, iOS 17+; Xcode project generated using XcodeGen.
- `crates/explorer-core/`: portable client domain logic.

The mobile apps use native navigation, lists, forms, file pickers, and secure storage. They do not embed the web UI. Dynamic sign-in, hosted payment checkout, and connected-wallet transactions use the system browser. Deploy this branch's web backend before using mobile sign-in: `/mobile-auth` is the new encrypted callback bridge.

## Shared core and platform boundaries

Rust implements genotype format detection/parsing, bounded gzip decoding, variant matching, OR/beta scoring, quality/evidence interpretation, result serialization, preview selection, report selection and prompts, personalization parsing, provider configuration, promo verification, native access policy, encrypted portable vaults, and native nilAI authentication tokens. The report regression fixtures preserve the prior web report selection and prompt behavior.

Normal operations on all hosts use the same versioned JSON protocol: `{version:1, operation, input}` returns `{ok:true,value}` or `{ok:false,error}`. `crates/explorer-core/src/lib.rs` lists operations. Recoverable input errors do not panic. Large native DNA imports use a UniFFI byte-buffer entry point to avoid base64/JSON copies; this calls the same bounded decoder, parser, hash function, and session implementation. Rust sessions own native genotype/result state; closing a session invalidates its handle.

The web adapter (`lib/core.ts`) loads an import-free WASM module synchronously, including in workers and server rendering. Existing TypeScript functions retain their public signatures and delegate domain work to Rust. Kotlin and Swift call the same entry point through generated UniFFI bindings, using a native shared/static library respectively. Generated bindings, WASM source, native libraries, and Xcode projects are ignored and regenerated from the locked Rust workspace.

HTTP transport, provider SDK integration, cancellation, UI state, browser IndexedDB, platform file access, and OS credential storage remain in their hosts. The backend's PostgreSQL/pgvector search, authentication verification, Stripe, and blockchain services remain server-side. The web app retains its IndexedDB catalog cache and WebCrypto nonextractable device key; mobile Run All fetches catalog pages from the same API and scores on device. Native catalog browsing requires a network connection.

## Features

Both native apps provide DNA import, exact/semantic search and trait filtering, study details and publication links, individual matching, Run All, saved-result filtering and TSV import/export, chat, Health/Healthspan/Top traits/Overview reports, optional personalization, provider settings, encrypted local and portable vaults, Dynamic sign-in, subscription refresh, promo entry, and hosted account/payment links. Chat and paid reports use subscription/promo access or consume an existing report pass through the backend. Buy passes and manage wallet payments on the website.

The layout and platform interactions differ from the web app. Mobile report output supports export as Markdown; Android displays the report text directly. Web-specific advertising, attribution, social-account linking, and browser catalog caching are not duplicated as native screens. Payment/account pages remain available in the system browser. Both native report screens expose follow-up questions generated by the shared core.

## Web development

Install Node 24, rustup, and the PostgreSQL/pgvector backend described in the main README. Then:

```sh
npm ci
npm run dev                 # builds WASM first
npm test                    # actual JS/WASM adapter regression tests
npm run core:test           # native Rust contract tests
npm run lint
npx tsc --noEmit
npm run build
```

Keep `POSTGRES_DB` pointed at your environment's local database during development. No database credentials or server provider keys are embedded in mobile apps. CI production builds do not require database access during compilation.

## Android

Requirements: JDK 21, Android SDK platform 35/build tools 35.0.0, NDK 27.2.12479018, Node 24, rustup. Set `ANDROID_HOME` to the SDK location. The checked-in Gradle wrapper pins Gradle 8.11.1 and verifies its SHA-256 checksum.

```sh
node scripts/build-native.mjs android arm64-v8a
cd apps/android
./gradlew assembleDebug testDebugUnitTest lintDebug
# Output: app/build/outputs/apk/debug/app-debug.apk
```

Host JVM tests load the real Rust library built by the script. For an x86 emulator, first build the matching Rust ABI and select it for packaging:

```sh
node scripts/build-native.mjs android x86_64
cd apps/android
./gradlew -PexplorerAbis=x86_64 assembleDebug connectedDebugAndroidTest
```

`-PexplorerAbis=arm64-v8a,x86_64` packages both, after generating both libraries. Release builds require your signing configuration. Debug builds permit `http://10.0.2.2:3000`, `localhost`, and `127.0.0.1` for the local backend; release catalog/account traffic requires HTTPS. User-configured Ollama traffic may use HTTP. Change the backend origin in Settings. An emulator's localhost is the emulator itself.

## iOS

Requires macOS, Xcode with iOS 17+ SDK/simulators, Node 24, rustup, and XcodeGen (`brew install xcodegen`).

```sh
node scripts/build-native.mjs ios simulator
xcodebuild -project apps/ios/Explorer.xcodeproj -scheme Explorer \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  -derivedDataPath apps/ios/build test CODE_SIGNING_ALLOWED=NO
# Substitute an installed simulator from: xcrun simctl list devices available
```

For a device: `node scripts/build-native.mjs ios device`, open the generated project, set your development team and signing, and run. Rust libraries are linked by platform and architecture. Generate both simulator architectures if building a universal simulator destination. `CARGO_TARGET_DIR` overrides are supported by Android and WASM generation; iOS project linkage expects the default repository `target/` directory.

The macOS CI job builds Rust, generates the project, selects an available iPhone simulator, and runs XCTest. iOS compilation and simulator tests run on macOS rather than this Linux workspace. The app build and all five XCTest tests passed in [CI run 39608592827](https://github.com/Monadic-DNA/Explorer/actions/runs/39608592827).

## Privacy, interoperability, and deployment

DNA stays in memory until a user explicitly saves an encrypted vault. Mobile vaults use the shared PBKDF2-SHA256/AES-256-GCM format with 600,000 iterations and a user passphrase; keys and nonces come from the OS random source. Android settings and tokens use Android Keystore encryption; iOS uses device-only Keychain entries. Local vaults are excluded from platform backups. Lock closes the Rust session and clears visible results/chat/report state. Exported files are controlled by the user's selected file destination.

`/portable-vault` on the web imports/exports the same encrypted snapshot as mobile. It imports into the active in-memory session; saving the existing browser vault is a separate action. Existing web encrypted genotype files remain compatible with the Rust decryptor. Portable vaults contain DNA and results, not provider credentials or account tokens.

Sign-in uses a fresh X25519 key and random state, expires after five minutes, encrypts the JWT to the initiating device, and returns through `monadicexplorer://auth`. Register the web origin with your Dynamic environment. Native account requests carry the existing bearer token. Changing the backend should be done only to a server you trust with your account token.

LLM use requires explicit result-sharing consent. Prompts go directly to the selected provider. HuggingFace needs a user-supplied key; Ollama uses the configured host; nilAI accepts a device key or the backend's one-use delegation flow. Native nilAI tokens are verified in regression tests using the existing Nillion SDK. Backend delegation retains its five-requests-per-minute limit; large Overview reports may require retrying or a user-provided nilAI key. Phone access to local Ollama requires reachable networking and appropriate platform transport configuration; production HTTPS endpoints are preferable.

## Validation scope

The Linux workspace validates Rust, the actual WASM adapter, TypeScript, ESLint, the Next.js production build, Android compilation, Android lint, and Kotlin/JNA calls into the real Rust library. CI also defines Android emulator navigation and macOS XCTest jobs. Device sign-in, real provider calls, purchases, signing, and store distribution require configured services and device testing; automated tests do not charge cards or submit personal DNA to providers.
